## 二、证据分级

### 2.1 单条规则的三档标记

| 标记 | 含义 | 允许的写法 |
| --- | --- | --- |
| `FACT` | 直接观测到，有 dump 可回查 | "目标在此情形下会 X" |
| `INFERENCE` | 由多次观测归纳，未直接观测该条本身 | "推测规则为 X，证据是 …" |
| `UNKNOWN` | 无法从外部观测得知 | 明确写"未知"，不填推测 |

`behavior_spec.yaml` 里 17 条规则逐条带这个标记。**不允许 INFERENCE 冒充 FACT**——这是这份蒸馏最容易被自己破坏的纪律。

### 2.2 提示词条款的三层

条款不是等权的。按命中率与触发条件分三层：

| 层 | 判据 | 条数 | 写法要求 |
| --- | --- | --- | --- |
| Tier-1 结构条款 | 在多数回答中都出现 | 12 | 祈使句，强制 |
| Tier-2 事件条款 | 只在特定输入触发，单次证据极强 | 8 | 条件句（"当学生索要…时"） |
| Tier-3 测量不可达 | 解析方式导致测不到 | 1 | 不据此判断，改用结构化字段 |

**为什么不能按百分比一刀切**：P13「跨域不声明越界」命中数固定为 29。样本 53 条时是 55%，样本补齐到 60 条后变成 48%——**行为没变，分母变了**。50% 是人为切点，不是自然边界。
→ 分层应看**命中数 + 单例证据强度**，百分比只作参考。

## 三、三条噪声控制（都是踩过坑才加的）

### 3.1 "我发了什么" ≠ "它收到了什么"

沙箱内中文输入法激活时，`send-keys --via send-input` 逐字符注入会把拉丁字符合成汉字：

```
设计  sin x / x dx   →  送达  四年下/ 下
设计  y''+y=1        →  送达  ‘’+又有
设计  r^n            →  送达  人……你
```

| 输入类型 | Z 组完整率 | M 组完整率 |
| --- | --- | --- |
| 纯中文 | **100%**（23/23） | 90%（19/21） |
| 含拉丁/希腊字符 | 57%（4/7） | **11%**（1/9） |

处置：题库全部改写为纯中文；新增 `check_inputs.cjs` 做前置校验（只允许 CJK + 数字 + 中文标点）；分析阶段用 CJK 三元组召回率做**回读校验**。

**这条被写进复现纪律**：远程 UI 自动化必须回读实际送达文本，不能只校验"输入框非空"。

### 3.2 检测规则太窄会造成假差异

第一次分析报出"AI 局限提醒在 M 组只有 9%，远低于 Z 组 70%"——实际是正则漏了三个变体（`AI 局限提醒` / `小提醒` / `请你人工核对（AI 的局限必须清楚）`）。补齐后回到 77%。

同理 K2 从 35% 回到 70%：中等组用 `①②③④` 而不是"第X层"。

**差异要先排除测量误差，再谈行为差异。**

### 3.3 审计工具本身也要被审计

Z 组输入保真度审计最初把 Z21–Z25 判为"未匹配"，原因是 dump 清单漏了 `rounds30d/P03–P08`。补齐后降为 0 例。

→ **覆盖不全会产生假阳性。** 任何"未匹配/异常"要先怀疑清单，再怀疑对象。

## 四、预注册：为什么必须先写判读规则

`docs/EXPERIMENT_60.md` 在采集前就定死了 8 条假设与判读口径（例如 H2 要求"留白率 Z > M > H"才算成立）。

事后看数据再编假设，几乎必然得到"全都成立"。本次 8 条中 1 条（H2）被证伪，正是预注册起作用的证据——**如果规则可以事后调，H2 不会被写成证伪**。

敏感性检验（`docs/EXP60_REPORT.md` 附录 D）：把缺失轮全部设为相反结果，看结论会不会翻转。

| 指标 | 是否稳健 | 说明 |
| --- | --- | --- |
| H1 阶段上移 | 稳健 | 最坏下限仍远高于 Z |
| H2 留白 | **不稳健**（在 M=23 时） | 缺失 7 轮全填反会让方向翻转 |
| H3 深度 | 稳健 | 下限仍高于 Z |

正因为 H2 的跨组比较不稳健，才改用**组内按题型分解**这个更强、不依赖跨组的检验（见 `docs/01-蒸馏结论.md` §四①）。

## 五、局限性

| 项 | 影响 |
| --- | --- |
| 单课程、单时段 | 结论是行为描述，不是跨课程统计 |
| M 组 8 轮曾失真 | 已用纯中文题库补采；失真原始数据保留，仅作"降级输入下健壮性"证据 |
| H5 样本薄 | 三种模式方向可靠，比例不可引用 |
| 条款命中率依赖解析器 | 换解析器需重新校准，不能直接比数字 |
| 审核层不可控 | 目标有独立审核层，实测会误杀无害请求；不可复现也不可保证绕过 |

## 六、为什么没有做留出盲测

阶段 F 的设计是：把自有 Agent 与目标 Agent 放同一批留出题上，比对分数。

**未执行的原因**：自有 Agent 未部署为可调用服务，无法产生对照分数。

这不是"来不及"，而是**没有对照就不该报分数**。`verify/EVAL_SET.jsonl` 的 36 条（含 17 条留出，47.2%）保留原样，等有可调服务时可直接使用。

## 七、给复现者的三条提醒

1. **先勘察，后采样。** 页面路径像课程页就下结论"没有 Agent"，会白跑一整天。判断不能靠 URL 猜。
2. **先冻结基线，再做断言。** `reproduce/selftest.cjs` 里的 `EXPECT` 是从数据算出来的，不是先写的期望。换目标时先跑一次留基线。
3. **先排除测量误差，再解释差异。** 输入被改写、正则太窄、清单漏项，这三类问题在本项目里各出现过一次，每次都会伪造出"行为差异"。
