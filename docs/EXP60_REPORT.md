### 5.4 三条推翻性新发现

**① 留白不由水平决定，由场景决定（推翻 H2，也推翻 v3 的隐含假设）**
零基础组不留白，是因为他们问的多是"这是什么/我适合吗"，本就没有推导可留白；
中等组带着具体卡点来问，反而被更完整地套进推导骨架。
→ 正确规则：**概念讲清楚不留白；推导/解题必须留白；规划类给清单不留白。**

**② 存在前置阻塞式澄清（推翻 v3 的"澄清一律后置"）**
M26 要"这一章的可背资料"，目标先问：
> 你说的"这一章"是哪一章？不同章节的"可背清单"结构完全不同，**我不猜**。

→ 正确规则：**能假设推进的走"先答后问"；无法定位推理起点、猜错即白做的走"前置阻塞"。**

**③ 能力名是开放生成，不是枚举**
M21 用了「**进化力**」，超出 v3 所列的判断力/学科交叉力/推导力/抽象力/结构力。
→ 正确规则：**能力名开放式生成，按本轮实际锻炼点命名。**

## 六、得出结论（Conclusion）

### 6.1 已可定论的部分

1. **五段外层骨架是强结构**，跨水平稳定（Z 83%、M 96%）。
2. **第 2 段内部结构随场景切换**，已知五种：四层认知梯度 / 自查清单 / 优先级清单 /
   原因拆解 + 最小行动 / 分步操作。
3. **教学协议真实生效且刚性**：推导与解题必须留白、必须指明关键步、必须把球踢回学生。
4. **澄清有两种模式**：假设推进（默认）+ 前置阻塞（无法定位起点时）。
5. **诚实条款优先于讨好**：资料缺失主动承认、不硬编答案、用学生自己的证据反驳自我贬低。
6. **边界三子型**处理方式完全不同：闲聊拉回、注入点名拒答且不署名、纯收尾用收尾三件套。
7. **结构完整度随学生具体性上升**，不随水平上升——这修正了"因材施教"的直觉理解。

# 附录 B｜数据质量审计：输入法改写（2026-11-15T22:25）

## B.1 发现

沙箱内中文输入法处于激活状态，`send-keys --via send-input` 逐字符注入时，
**拉丁字母序列被拼音规则合成了汉字**，导致实际送达目标 Agent 的问题与设计不符。

审计方法：从每轮 DOM 中取出实际送达的用户消息，与设计文本做 CJK 三元组召回率比较
（脚本 `evidence/audit_input_fidelity.cjs`，结果 `evidence/exp60/input-fidelity.json`）。

| 输入类型 | 条数 | 完整率（召回≥0.95） |

| 含拉丁字符 | 9 | **11%**（1/9） |
| 纯中文 | 21 | **90%**（19/21） |

## B.3 影响判定

**M13–M20（解题验证类 C，共 8 轮）的数据不能用于原设计目的。**
它们实际测的是「目标 Agent 如何应对表述混乱的输入」，而不是「如何指导一道具体习题」。

不过这批数据仍有独立价值：目标在 M17 中主动识别了输入异常
（"用户问题混乱……可能是语音识别错误"），仍给出了结构完整的回答并标注需人工核验。
这是一条**健壮性证据**，但不是解题辅导模式的证据。

已受影响的结论：
- K1–K8 在 M 组的通过率**不必修正**（结构条款与提问内容无关）
- L2 留白率、L3 深度词命中率**受轻微影响**（题面混乱会改变回答走向）
- H2「留白随水平降低被证伪」的判断**不受影响**（该结论主要来自 M21–M28 与 Z 组，均为纯中文输入）

## B.4 处置

1. 新增校验脚本 `evidence/check_inputs.cjs`：只允许 CJK 汉字、ASCII 数字、中文标点，
   任何拉丁字母或 π/∫/δ/Λ/²/⁻ 等符号一律报风险。
2. H 组 30 题**全部重写为纯中文**（`exp60/h_q2.json`，校验 30/30 安全）：
   `Hadamard`→阿达马、`Sturm－Liouville`→施图姆刘维尔、`r^n`→半径的整数次幂、
   `Λ`→那个分离常数、`z^2 sin z`→复变量平方乘以该复变量的正弦。
3. M 组解题类 8 题重写为纯中文（`exp60/mc_q2.json`，校验 8/8 安全），供必要时重采。
4. 执行脚本改用新题库，并加入**锁屏早退**（检测到 `no_interactive_desktop` 立即中止并记录，
   不再空耗 120 秒等待）。

## B.5 教训

> 远程 UI 自动化里，**"我发了什么"和"它收到了什么"是两件事**。

在跨 IME、跨输入法状态的场景下，必须对输入做**回读校验**（比较实际送达文本与设计文本），
而不能只校验"输入框非空"。本次是在分析阶段才靠召回率对比发现，代价是 8 轮数据失真。

## D.2 留白率按题型分解（更强的检验）

| 题型 | Z 零基础 | M 中等 |
| --- | --- | --- |
| B 推导证明 | **5/5 = 100%** | **6/6 = 100%** |
| C 解题验证 | **5/5 = 100%** | **3/3 = 100%** |

→ 「**留白由场景决定，不由学生水平决定**」这一表述得到支持，

"解题类必留白"在**输入完整**的前提下依然成立。

准确表述：**输入完整时，推导类与解题类的留白率为 100%（两组一致）；
输入被改写时方向未知。**

## F.5 三个反直觉结论

### ① 留白不随水平降低，反而上升

从零基础到较高水平，留白率 53% → 57% → 77%。

→ **留白由场景决定，不由水平决定**（附录 D.2 的按题型分解：推导 11/11、解题 8/8 均为 100%）。

这两类按协议**不署名**。属正确行为，不是缺陷。
